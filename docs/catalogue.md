# Catalogue

## Adapters

Storefront rows and SocialPanel24 stay in separate modules:

- Retail / sheet: `supabase/functions/_shared/retail-adapter.js` + `retail-catalogue.js`
- Provider: `supabase/functions/_shared/socialpanel24.js`

Sheet-compatible GET body: `{ ok: true, data: [...] }` with `ID`, `Platform`, `Service`, `Description`, `Price`, comma-separated `Inputs`, `Visible`, `socialpanelId`, plus lowercase aliases. `commentsList` becomes canonical `comments`.

Optional remote sheet JSON: env `RETAIL_CATALOGUE_URL`. Otherwise the bundled retail catalogue is used.

Optional `RETAIL_SOCIALPANEL_IDS` JSON (`{"01":"123","02":"456"}`) overlays provider ids onto those rows so mapping can be stored in `app_secrets` without editing `retail-catalogue.js`.

## Join

Each visible retail row’s `socialpanelId` is matched to provider `service`. Missing, unmapped, or unsupported types (`Subscriptions`, unknown types) are disabled. Public JSON omits provider ids, provider rates, and costs.

Internal model: id, platform, type, label, description, enabled, inputs, min/max/step/default, currency, retail rate (minor units), rate unit, quantity mode. Provider cost stays server-side.

## Cache

- Memory TTL: 5 minutes (`CATALOGUE_TTL_MS`)
- Provider fetch timeout: 8 seconds (`SOCIALPANEL24_TIMEOUT_MS` / `CATALOGUE_TIMEOUT_MS`)
- On provider failure, serve stale cache up to 1 hour (`CATALOGUE_STALE_MS`). A missing API key is not cached durably, so adding `SOCIALPANEL24_API_KEY` / `RETAIL_SOCIALPANEL_IDS` can take effect within 30 seconds.
- Optional `catalogue_cache` table via the store

## Frontend

`js/api/services-api.js` calls Edge Function `catalogue`, then falls back to `#services-data`. Loading / empty / error+retry live in `js/components/catalogue-states.js`. Static headings and a `<noscript>` card fallback are generated by `scripts/build.mjs`.

Live catalogue joins bundled SocialPanel24 service ids (Instagram 11456/12472/12364, TikTok 11655/12474, YouTube 12610). Comments are priced `per_1000` because panel rates are per 1,000 comments; billable quantity is still the comment-line count. Unmapped rows stay listed and not purchasable.
